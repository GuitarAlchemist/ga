# Hermes Agent, OpenClaw, and V-JEPA 2: mechanisms for the GA Cloud Factory

**Type:** primary-source design research, not a commitment to adopt an upstream runtime

**Source snapshots:** Hermes Agent `26e0b1c`; OpenClaw `e75ae0c`; V-JEPA 2 `204698b`

## TL;DR

Use Hermes and OpenClaw as mechanism catalogs, not runtimes to embed. The Cloud Factory should keep its bounded work-packet queue and add a durable append-only event log, per-physical-workspace fenced leases, one isolated worktree per mutable packet, capability snapshots, hierarchical budgets, authorized cascade stop, and verification evidence invalidated by any later edit or HEAD change. BAML remains typed parsing at LLM leaves followed by canonical validation.

V-JEPA 2 is **not needed for the tracer bullet**. Its useful idea is only conceptual: predict a compact next-state representation under candidate actions, rank candidates, execute one reversible step, observe, and re-plan. A learned predictor may later run in shadow mode for queue prioritization after GA has a representative trajectory corpus and proves lift over deterministic heuristics. It must never grant authority, acquire/release a lease, validate Git state, approve a command, certify evidence, or merge.

## Method and source boundary

I inspected only first-party README, documentation, source, tests, release notes, and the V-JEPA 2 paper/blog. Commit-pinned links below distinguish implementation facts from GA-specific inference. Release pages were checked for current behavior and release-evidence practice: [Hermes v2026.7.30](https://github.com/NousResearch/hermes-agent/releases/tag/v2026.7.30) and [OpenClaw v2026.7.1](https://github.com/openclaw/openclaw/releases/tag/v2026.7.1).

## Recommended mechanisms

| Concern | Primary-source fact | GA Cloud Factory inference |
|---|---|---|
| Queue and lifecycle | Hermes Kanban keeps durable SQLite tasks and run history, requires worker heartbeats, reclaims stale/crashed runs, records protocol violations, retries only to a bound, then auto-blocks; its own docs explicitly limit the board to one host ([Kanban](https://github.com/NousResearch/hermes-agent/blob/26e0b1c12c2bbc2d1ef4640df18abff2d737445a/website/docs/user-guide/features/kanban.md)). OpenClaw serializes each session while applying a separate global lane cap, supports explicit follow-up/collect/interrupt semantics, preserves an authorized cancel identity for queued work, and diagnoses/recoveries stuck lanes ([queue](https://github.com/openclaw/openclaw/blob/e75ae0c9a96406e169127a923bf78b033e5aafc1/docs/concepts/queue.md)). | Keep `discover -> classify -> claim -> isolate -> mutate -> verify -> review -> handoff/stop`, but persist every transition as an append-only event with actor, packet version, reason, and idempotency key. Cancellation must be packet/owner-scoped. A successful process exit without a terminal packet transition is a protocol violation, not completion. Retry by classified failure; exhaust to `blocked`/`quarantined`, never an endless prompt loop. |
| Agent fan-out | OpenClaw makes spawn non-blocking, caps global concurrency, active children, depth, and runtime, derives completion status from runtime outcome rather than model prose, and cascades `/stop` through descendants ([subagents](https://github.com/openclaw/openclaw/blob/e75ae0c9a96406e169127a923bf78b033e5aafc1/docs/tools/subagents.md)). | The tracer runs one packet. Later throughput may run independent packets only, each in its own worktree. Use explicit root/child accounting and cascade cancellation. Do not infer success from an agent saying “done”; use exit status plus the packet's completion contract and evidence. |
| Workspace isolation | OpenClaw states that a workspace is only a default cwd, not a sandbox. Its sandbox can be per session, expose no host workspace or only `ro`/`rw`, run with no network and a read-only root, and bind each extra path with its own access mode ([workspace](https://github.com/openclaw/openclaw/blob/e75ae0c9a96406e169127a923bf78b033e5aafc1/docs/concepts/agent-workspace.md), [sandboxing](https://github.com/openclaw/openclaw/blob/e75ae0c9a96406e169127a923bf78b033e5aafc1/docs/gateway/sandboxing.md)). Hermes tests worktree isolation as a first-class Kanban property ([test](https://github.com/NousResearch/hermes-agent/blob/26e0b1c12c2bbc2d1ef4640df18abff2d737445a/tests/hermes_cli/test_kanban_worktree_isolation.py)). | Discovery is read-only over primary checkouts. Mutation happens only in a fresh packet worktree keyed by repo + base SHA + packet id. Default mounts: source packet `rw`, other ecosystem repos `ro` or absent, secrets absent, network off until explicitly needed. Treat path allowlists as ergonomics; the sandbox/OS boundary is the security control. |
| Skills and tools | Hermes exposes skills progressively as catalog -> full `SKILL.md` -> referenced file, reducing prompt cost; marketplace installs are scanned and a “dangerous” verdict cannot be forced ([skills](https://github.com/NousResearch/hermes-agent/blob/26e0b1c12c2bbc2d1ef4640df18abff2d737445a/website/docs/user-guide/features/skills.md)). OpenClaw computes a final per-agent skill allowlist across prompt, discovery, sandbox sync, and snapshots; it snapshots eligibility per session and warns that this is not shell authorization ([skills](https://github.com/openclaw/openclaw/blob/e75ae0c9a96406e169127a923bf78b033e5aafc1/docs/tools/skills.md)). | Resolve a minimal packet capability manifest at claim time: skill names + content digests, tools, command shapes, mounts, credentials, and BAML client/schema versions. Load skill bodies/references on demand. Changing the manifest invalidates the claim or requires a new packet generation. A skill can explain a procedure; it cannot widen authority or shell access. |
| Memory and continuity | Hermes separates compact always-present memory from on-demand FTS session search and persists canonical transcripts in SQLite ([memory](https://github.com/NousResearch/hermes-agent/blob/26e0b1c12c2bbc2d1ef4640df18abff2d737445a/website/docs/user-guide/features/memory.md), [session lifecycle](https://github.com/NousResearch/hermes-agent/blob/26e0b1c12c2bbc2d1ef4640df18abff2d737445a/docs/session-lifecycle.md)). OpenClaw keeps curated Markdown memory separate from indexed daily notes and explicitly says memory does not enforce policy ([memory](https://github.com/openclaw/openclaw/blob/e75ae0c9a96406e169127a923bf78b033e5aafc1/docs/concepts/memory.md)). Its shared state log assigns monotonic versions, coalesces watcher notices, and reconciles exact deltas via `changesSince`; a history gap forces a full refresh ([session state](https://github.com/openclaw/openclaw/blob/e75ae0c9a96406e169127a923bf78b033e5aafc1/docs/concepts/session-state.md)). | Split three stores: (1) authoritative packet/event/lease state; (2) immutable evidence blobs; (3) human narrative/digests. Resume from the authoritative state version, then compare repo HEAD and dirty digest before acting. Narrative memory can suggest context but cannot prove ownership, freshness, approval, or completion. Use coalesced stale notices, then exact delta/full reconciliation. |
| Observability and evidence | Hermes' verification ledger is passive, records recognized command results, never upgrades a targeted check to “repo green,” and marks evidence stale after a later file edit ([source](https://github.com/NousResearch/hermes-agent/blob/26e0b1c12c2bbc2d1ef4640df18abff2d737445a/agent/verification_evidence.py)). Its observer hooks cover model/tool/approval/subagent lifecycles and are explicitly not allowed to change execution semantics ([observability](https://github.com/NousResearch/hermes-agent/blob/26e0b1c12c2bbc2d1ef4640df18abff2d737445a/docs/observability/README.md)). OpenClaw propagates request-scoped W3C traces and exports token, cost, duration, model-call, tool, and recovery metrics; raw content is off by default and content capture is bounded/redacted/opt-in ([OpenTelemetry](https://github.com/openclaw/openclaw/blob/e75ae0c9a96406e169127a923bf78b033e5aafc1/docs/gateway/opentelemetry.md)). | Every claim, mutation, model call, tool call, approval, verifier, review, push, stop, and recovery attempt gets a trace/event id. Evidence must bind `{packet_generation, repo, worktree, head_sha, dirty_digest, command, exit_code, timestamps, toolchain}`. Any edit or HEAD/toolchain/capability change stales it. Keep telemetry metadata-only by default; store bounded redacted excerpts only where needed. Observers must not approve or mutate. |
| Concurrency and leases | Hermes' turn lease uses owner key + generation and identity-checked idempotent release; its tests ensure a stale generation cannot free a newer holder ([source](https://github.com/NousResearch/hermes-agent/blob/26e0b1c12c2bbc2d1ef4640df18abff2d737445a/gateway/turn_lease.py), [tests](https://github.com/NousResearch/hermes-agent/blob/26e0b1c12c2bbc2d1ef4640df18abff2d737445a/tests/gateway/test_turn_lease.py)). OpenClaw's host-owned SQLite lease exposes `assertOwned`/`assertOwnedInTransaction`, tracks PID/start time, uses exact-owner release, and can make release failure strict ([state lease](https://github.com/openclaw/openclaw/blob/e75ae0c9a96406e169127a923bf78b033e5aafc1/src/state/openclaw-state-lease.ts)). Its worktree lease uses a random token, PID/start time, persistent cleanup retry, and guards against an old cleanup unlocking a newer holder ([worktree lease](https://github.com/openclaw/openclaw/blob/e75ae0c9a96406e169127a923bf78b033e5aafc1/src/agents/worktrees/run-lease.ts)). | Gaia's claim must become a transactional fenced lease over canonical physical worktree identity and overlapping paths: `{lease_id, generation/fence, owner_session, pid, process_start, base_sha, dirty_digest, acquired, heartbeat, expires}`. Re-check exact ownership inside the same transaction immediately before each mutation boundary and postflight write. A stale release may release only its exact token/generation. TTL is crash recovery, not proof that a known-live owner is dead. Timeout or uncertain ownership is fail-closed: stop/requeue. |
| Budgets and kill switches | Hermes has per-agent iteration counters and goal turn budgets, while Kanban bounds runtime and failure retries ([iteration budget](https://github.com/NousResearch/hermes-agent/blob/26e0b1c12c2bbc2d1ef4640df18abff2d737445a/agent/iteration_budget.py), [goals](https://github.com/NousResearch/hermes-agent/blob/26e0b1c12c2bbc2d1ef4640df18abff2d737445a/website/docs/user-guide/features/goals.md)). OpenClaw bounds automatic restart recovery to three charged dispatch attempts and tombstones a repeatedly failing session; an uncertain post-dispatch outcome keeps its charge to avoid duplicate replay ([restart recovery](https://github.com/openclaw/openclaw/blob/e75ae0c9a96406e169127a923bf78b033e5aafc1/docs/gateway/restart-recovery.md)). | Use one atomic hierarchical budget ledger: factory -> packet -> child. Debit wall time, attempts, model/tool calls, tokens/cost, files, and diff size before dispatch; children cannot mint independent capacity. Preserve charges for uncertain side effects. Budget exhaustion emits a durable `stopped` event and cascades cancellation. `STOP`/HALT and authority revocation are checked at every mutation boundary, not only between turns. |
| Human approval | Hermes separates hard unoverrideable blocks from dangerous-command approval and denies on approval timeout, but documents that file-tool guards do not constrain shell access ([security](https://github.com/NousResearch/hermes-agent/blob/26e0b1c12c2bbc2d1ef4640df18abff2d737445a/website/docs/user-guide/security.md)). OpenClaw supports per-agent binary-and-argument allowlists, `ask` on misses, and `askFallback: deny`; it also documents explicit `full`/YOLO bypasses ([exec approvals](https://github.com/openclaw/openclaw/blob/e75ae0c9a96406e169127a923bf78b033e5aafc1/docs/tools/exec-approvals.md)). | Preserve the packet authority ladder `inspect < edit < push < ready < merge`. Approval is one-shot and bound to packet generation, exact HEAD/action digest, actor, expiry, and scope. Timeout denies. Protected paths, destructive Git, one-way doors, external messages, `ready`, and `merge` require explicit deterministic policy/operator authority. BAML or another LLM may format an approval request, never decide it. |

## BAML boundary

**Inference from the sources and the existing GA plan:** BAML is useful where an LLM's untrusted text must become a typed proposal. It should emit a versioned leaf DTO such as `ClassificationProposal`, `VerifierInterpretation`, or `NextActionProposal`; canonical C#/F#/Rust schema and domain validation must then accept or reject it. Queue state, lease ownership, budgets, authorization, evidence validity, and Git/GitHub mutations remain deterministic and transactional. A parse repair is not a semantic repair, and no BAML result may be treated as a receipt issued by the same actor whose spending or work it is meant to attest.

## V-JEPA 2 assessment

### Facts

- V-JEPA 2 pretrains a video encoder/predictor with masked **latent-feature** prediction rather than a pixel-generation objective. The released V-JEPA 2 encoders range from 300M to 1B parameters; the action-conditioned checkpoint uses the giant encoder and the official demo assumes a GPU ([official README](https://github.com/facebookresearch/vjepa2/blob/204698b45b3712590f06245fbfba32d3be539812/README.md)).
- V-JEPA 2-AC freezes the visual encoder and trains an autoregressive predictor of future visual representations conditioned on robot actions and proprioception, using about 62 hours of DROID robot video ([paper, §3](https://arxiv.org/abs/2506.09985)).
- Planning evaluates candidate action sequences against a goal in representation space, executes only the first chosen action, observes again, and re-plans (receding-horizon/model-predictive control). The published manipulation results are task-dependent rather than safety guarantees; the paper also reports degradation at longer anticipation horizons and limited known-domain generalization ([paper](https://arxiv.org/abs/2506.09985), [Meta overview](https://ai.meta.com/blog/v-jepa-2-world-model-benchmarks/)).

### Verdict for Cloud Factory / Gaia / BAML

**Not needed for the tracer bullet.** Local-work reconciliation already has fully observable typed state: Git refs, dirty-path digests, processes, sessions, claims, PRs, verifier exits, and approvals. Replacing exact queries with a 1B-parameter visual world model would add GPU/dependency/data cost while weakening auditability. V-JEPA 2's released action space and evidence concern physical robot/video dynamics, not repository control planes.

**Later evidence-gated use, if any:** after the factory has accumulated a versioned corpus of representative packet trajectories `(typed state, proposed action, observed next state/outcome)`, test a small action-conditioned predictor in **shadow mode** to rank reversible next actions or forecast likely verifier failure/stall. Adopt only if a held-out benchmark demonstrates calibrated improvement over deterministic heuristics within an explicit local compute/cost budget and the recommendation can be explained by retrieved trajectories. Even then, execute one bounded action and re-observe, borrowing the receding-horizon pattern—not the V-JEPA 2 model itself.

**Hard exclusion:** learned predictions may never control admission, authorization, protected-path checks, lease ownership/fencing, kill switches, budget debits, evidence freshness, schema validation, push/ready/merge authority, or incident recovery. Those paths must remain deterministic and fail-closed.

## Mechanisms not to copy

1. **Hermes' lease timeout fails open.** Its per-session turn lease deliberately proceeds unserialized after timeout. That availability trade-off is unacceptable for overlapping filesystem/Git mutations; Gaia must stop or requeue on uncertain ownership ([source](https://github.com/NousResearch/hermes-agent/blob/26e0b1c12c2bbc2d1ef4640df18abff2d737445a/gateway/turn_lease.py)).
2. **Independent child budgets.** Hermes documents that total parent + subagent iterations can exceed the parent's cap. Factory children must draw from the root packet/factory ledger ([source](https://github.com/NousResearch/hermes-agent/blob/26e0b1c12c2bbc2d1ef4640df18abff2d737445a/agent/iteration_budget.py)).
3. **Single-host assumptions presented as distributed coordination.** Hermes Kanban explicitly relies on local SQLite and host-local PIDs. Do not share it or a Gaia JSONL file across hosts without a real transactional/distributed lease; keep the tracer local ([Kanban](https://github.com/NousResearch/hermes-agent/blob/26e0b1c12c2bbc2d1ef4640df18abff2d737445a/website/docs/user-guide/features/kanban.md)).
4. **In-process locks/queues as durable ownership.** They are useful scheduling layers, not crash-safe authority. The durable database lease/fence is authoritative; process queues are optimization.
5. **`rw` primary checkout or shared sandbox scope.** Mutable packets get isolated worktrees. Shared environments and broad host binds defeat per-packet provenance.
6. **Skill/tool allowlists mistaken for security.** Both projects warn that procedure/catalog gating is not a shell/filesystem boundary. Pin the manifest and enforce sandbox/OS/credential policy separately.
7. **Implicit skill-to-command trust, broad `full`/YOLO, or LLM-only “smart approval.”** A model can advise; deterministic hard blocks and explicit operator authority remain the floor. Approval absence/timeouts deny.
8. **Best-effort announce as the completion record.** OpenClaw notes that subagent announce can be lost on restart. Completion is an authoritative state transition plus evidence, with notifications derived from it ([subagents](https://github.com/openclaw/openclaw/blob/e75ae0c9a96406e169127a923bf78b033e5aafc1/docs/tools/subagents.md)).
9. **Automatic replay when an external side effect is uncertain.** Preserve the charged attempt and reconcile the remote/Git state before deciding whether to retry, following OpenClaw's uncertainty accounting.
10. **Learned world-model output in a safety or certification path.** V-JEPA 2 demonstrates useful predictive planning, not exact policy enforcement or formal safety.

## Minimal tracer-bullet delta

The current Gaia packet remains the right first slice. The upstream research suggests only these additions to the existing plan:

1. Store packet transitions and evidence references in a local transactional database/event log; keep exported JSON/Markdown as views.
2. Claim the canonical physical worktree + path set using an exact-owner fencing token and re-check it transactionally at every mutation/postflight boundary.
3. Materialize one fresh worktree; pin base SHA, dirty digest, capability/skill digests, BAML schema/client versions, verifier commands, and authority.
4. Run one bounded repair, then verifier and independent review on the same HEAD. Any later edit invalidates both.
5. Persist runtime-derived completion, usage/cost, residual risk, and the next authority boundary; release only the exact lease generation and stop before merge.

This deepens the existing reconciliation design without turning the Cloud Factory into a new general-purpose agent runtime or adding V-JEPA 2 to the dependency graph.
